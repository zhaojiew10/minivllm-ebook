# 阅读与实践指南

## 如何使用本书

本书把 MinivLLM 的官方技术路线、源码与课程素材整理为 6 个部分、15 章。每章围绕一个概念或工程闭环展开，正文可以脱离视频独立阅读。建议先抓住“请求—调度—数据准备—模型执行—采样—停止与释放”的主线，再深入某个 Triton kernel。

## 环境与版本

阅读正文不需要准备运行环境。若要执行书中推理和 Triton 基准，MinivLLM 的 `pyproject.toml` 要求 Python `>=3.11,<3.12`，并需要 CUDA-capable GPU。书中源码快照及 commit 见[资料来源与版本](sources.md)。

## 实践原则

每章实验都应回答三个问题：**结果是否正确、性能是否改善、结论能否复现**。

1. 先保存源码版本、配置和完整命令，再修改实现。
2. 为 kernel 保留简单的 PyTorch 或高精度参考实现，覆盖非整块、非 2 幂尺寸和乱序 block table。
3. 先验证数值，再进行预热和多次计时；`correct=NO` 的结果不参与加速比计算。
4. 固定模型快照、dtype、输入与输出长度、采样参数和硬件环境。
5. 区分 kernel 时间、单步调度时间和端到端时延，不用单个 `tokens/s` 替代完整评估。
6. 不把“源码包含某个类或参数”直接理解为该功能已经闭环，例如 Prefix Caching 还需检查历史 KV 读取和位置偏移。

## 如何使用代码示例

书中代码优先突出核心机制，部分片段省略完整配置、进程启动、异常处理和资源管理。伪代码会明确标注，不能直接当作项目文件执行。实际修改时应：

- 对照本书所用 commit 阅读完整函数，而不是只复制片段；
- 保留输入形状、block table、slot mapping 和序列状态的不变量；
- 为修改补充独立测试，尤其是跨块边界、抢占、缓存释放和多进程序列化；
- 将未运行的复现步骤与已经获得的实测结果分开记录。

## 配图和性能数字

课件页与视频帧用于解释结构和代码流程，图注标明素材类型和来源。SVG 示意图用于辅助理解概念，不是性能分析工具输出。

官方技术路线中的性能数据来自作者的单张 A6000 环境。本书引用时保留硬件和测试条件，并标为官方结果；除非明确写为本地实测，否则不应把这些数字当作当前机器上的复现结果。

## 阅读检查清单

- 本章解决了推理链路中的哪个问题？
- 输入输出张量、序列状态或物理地址如何对应？
- 哪些边界条件会破坏正确性？
- 功能是在当前源码中真正闭环，还是只有字段、注释或未来扩展入口？
- 性能结论来自理论分析、官方测量还是本地实验？测量范围是否明确？
