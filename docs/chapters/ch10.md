# 第 10 章 组装 Qwen3 与 Llama 3.2 模型

模型文件并不是对 Hugging Face 实现的简单复制。MinivLLM 将嵌入、注意力、前馈网络、分页 KV Cache 和张量并行线性层重新组合，使同一套执行引擎能够服务 Qwen3-0.6B 与 Llama-3.2-1B-Instruct。本章沿一次前向传播阅读模型组装方式，同时区分源码已经实现的能力与配置项表面承诺的能力。

## 源码定位与模型选择

本章涉及的主要文件如下，行号对应当前源码，后续修改后可按类名重新定位。

| 文件 | 关键位置 | 职责 |
|---|---|---|
| `src/myvllm/engine/model_runner.py` | `ModelRunner.__init__`，第 29—77 行 | 按模型名构造网络、移至 GPU、加载权重 |
| `src/myvllm/models/qwen3.py` | 第 11—342 行 | Qwen3 注意力、MLP、Decoder、Model 与 CausalLM |
| `src/myvllm/models/llama.py` | 第 8—313 行 | Llama 3.2 对应组件 |
| `src/myvllm/layers/embedding_head.py` | 第 12—93 行 | 词表并行嵌入与 LM Head |
| `src/myvllm/layers/attention.py` | `Attention.forward`，第 472—518 行 | 写入 KV Cache，分流 Prefill 与 Decode 注意力 |
| `src/myvllm/utils/loader.py` | 第 16—214 行 | 读取 safetensors，合并并复制检查点权重 |

`ModelRunner` 先用 `Path(config['model_name_or_path']).name` 取得路径最后一段，再进行精确匹配：只识别 `Qwen3-0.6B` 和 `Llama-3.2-1B-Instruct`，其他名称进入 `Unsupported model` 分支。因此，更换本地目录名并不是无影响的；即使目录内检查点相同，目录 basename 不符合这两个字符串也不会被接受。

模型的调用链可以概括为：

1. `input_ids` 经 `VocabParallelEmbedding` 变成隐藏状态；
2. 多个 Decoder Layer 依次执行 RMSNorm、自注意力、残差连接和 SwiGLU 前馈网络；
3. 最后的 RMSNorm 合并末层残差并归一化；
4. `ForCausalLM.forward` 返回隐藏状态，而不是 logits；
5. `ModelRunner.run_model` 再调用 `compute_logits`，由 `ParallelLMHead` 选出需要采样的位置并计算词表分数。

这种拆分很重要：主干不需要为 Prefill 中每个 token 都保留一份完整 logits，LM Head 可以在 Prefill 时只处理每条序列的最后一个隐藏状态。

## 输入排布：二维变长 token 流

以下用 `T` 表示一个批次中所有序列本次输入 token 数之和，用 `H` 表示隐藏维，`Hq`、`Hkv` 分别表示查询头和 KV 头数，`D` 表示每个头的维度，`I` 表示 MLP 中间维。引擎实际传入的是拼接后的一维 `input_ids`，不是右侧补齐的 `[batch, seq_len]` 矩阵。

| 阶段 | 典型形状 | 含义 |
|---|---|---|
| 输入 | `[T]` | 多条序列的 token 连续拼接 |
| 嵌入输出 | `[T, H]` | 每个 token 的隐藏向量 |
| Q / K / V 重塑 | `[T, Hq, D]` / `[T, Hkv, D]` | 将投影末维拆成头和头内维 |
| 注意力输出 | `[T, Hq * D]` | 展平头维，供输出投影使用 |
| Decoder 输出 | `[T, H]` | 恢复隐藏维 |
| Prefill logits | `[S, V]` | `S` 条序列各取最后一个位置，`V` 为词表大小 |
| Decode logits | `[S, V]` | 每条序列本步只有一个输入 token |

两个模型类虽然保留了 QKV 对三维批量输入的分支，但 `ModelRunner.prepare_prefill` 与 `prepare_decode` 生成的分别是 `[T]` 和 `[batch]`，所以阅读主流程时应以二维隐藏状态 `[T, H]` 为准。

`Qwen3Model.forward` 和 `LlamaModel.forward` 的主体几乎相同：

```python
x = self.embed_tokens(input_ids)
residual = None
for layer in self.layers:
    x, residual = layer(x, residual)
x, _ = self.norm(x, residual)
return x
```

这里的 `x` 不始终是“尚未归一化的最终隐藏状态”，`residual` 也不只是临时副本。两者共同携带融合残差计算所需的中间结果。

## Decoder Layer：融合残差与 RMSNorm

`layers/layernorm.py` 中的 `LayerNorm` 名称容易让人误以为它是均值方差归一化；其实现是 RMSNorm。传入 `residual` 时，`residual_rms_forward` 先执行 `x = x + residual`，再返回 `(RMSNorm(x), x)`。

Qwen3 与 Llama 的 Decoder 都采用同一结构：

```python
if residual is not None:
    x, residual = self.input_layernorm(x, residual)
else:
    residual = x
    x = self.input_layernorm(x)
x = self.self_attn(x, positions=positions)
x, residual = self.post_attention_layernorm(x, residual)
x = self.mlp(x)
return x, residual
```

第一层先把嵌入保存为残差，再归一化后送入注意力。注意力输出与嵌入残差相加，经第二个 RMSNorm 后进入 MLP；与此同时，未归一化的加和保存在 `residual` 中。下一层的 `input_layernorm` 再把上一层 MLP 输出与该残差相加。最终 `Model.forward` 的末层范数完成最后一次“加残差并归一化”，因此不需要在循环外另写一次残差连接。

### 位置索引来自执行上下文

两个 Decoder 都通过 `get_context()` 判断阶段，而不是从函数参数接收位置：

- 批量 Prefill 且 `cu_seqlens_q` 存在时，根据相邻累计长度得到每条序列的本次 query 长度，并分别从 `0` 开始生成位置；
- 单序列 Prefill 使用 `torch.arange(x.size(0))`；
- Decode 使用 `context.context_lens - 1`，即当前最后一个 token 的绝对位置。

这解释了为什么模型调用只有 `input_ids`：位置、KV 写入地址和块表都存放在全局 `Context` 中。也意味着当前 Prefill 位置生成假设 query 从零开始；若将来跳过已缓存前缀，就必须同时加入位置偏移，不能只减少 `input_ids`。

## 注意力：合并 QKV、GQA 与 RoPE

### 一次投影，三次切分

两种模型都使用 `QKVColumnParallelLinear`，再按本 rank 的宽度切分：

```python
qkv = self.qkv_projection(x)
q, k, v = qkv.split([self.q_size, self.kv_size, self.kv_size], dim=-1)
q = q.view(-1, self.num_heads, self.head_dim)
k = k.view(-1, self.num_kv_heads, self.head_dim)
v = v.view(-1, self.num_kv_heads, self.head_dim)
```

在 `world_size = 1` 时，按 `main.py` 与 `main_llama32.py` 的配置可得到下面的静态尺寸关系。它们是配置代入后的推导，不是性能测量结果。

| 模型 | `H` | `Hq` | `Hkv` | `D` | Q 宽 | K、V 各自宽度 | 合并 QKV 宽 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Qwen3-0.6B | 1024 | 16 | 8 | 128 | 2048 | 1024 | 4096 |
| Llama-3.2-1B-Instruct | 2048 | 32 | 8 | 64 | 2048 | 512 | 3072 |

`Hkv < Hq` 表明二者都使用分组查询注意力。注意力内核通过查询头编号整除“每个 KV 头服务的查询头数”，让多个 Q 头共享同一份 K/V。Qwen3 的 `1024 / 16 = 64` 不能拿来替代 `head_dim`：当前配置明确设置 `D = 128`，Q 投影总宽度也不必等于隐藏维。

`Attention.forward` 先按 `slot_mapping` 把当前 K/V 写入分页缓存，再选择计算路径。Prefill 调用基于本轮 Q/K/V 的 FlashAttention；Decode 则利用 `block_tables` 和 `context_lens` 从 KV Cache 读取历史，执行分页注意力。两条路径使用相同的缩放公式 `self.scale / sqrt(head_dim)`。

TP 大于 1 时，还必须区分“本地 reshape 正确”与“Attention 收到的头数正确”。`LlamaAttn` 确实用本地的 `self.num_heads`、`self.num_kv_heads` 重塑 Q/K/V，但构造 `Attention` 时传入的却是未分片的 `num_qo_heads`、`num_kv_heads`。于是下游内核启动、地址步长和最终输出展平仍按全局头数解释本地张量，形状契约不一致；输出 reshape 也无法把本地元素数变成全局头数所要求的宽度。这是**确定性的多卡阻断**，不是一般的待验证项，也不会因本地 reshape 正确而消失。Qwen3 的对应构造传递的是本地头数，不能据此替 Llama 路径背书。

### Qwen3 与 Llama 3.2 的差异

Qwen3 在 `qkv_bias is False` 时，对形状为 `[T, Hq, D]` 和 `[T, Hkv, D]` 的 Q、K 分别施加按 `head_dim` 归一化的 `q_norm`、`k_norm`，随后才做 RoPE；V 不做这一归一化。源码把这个操作放在条件语句中，所以不应脱离该条件泛化为所有配置都执行。

Llama 3.2 没有 Q/K Norm。它构造 `RotaryEmbedding(..., is_llama3=True)`，按源码中的 `factor=32`、高频因子 `4`、低频因子 `1` 和原始最大位置 `8192` 调整逆频率；Qwen3 则使用普通 RoPE。两者都只旋转 Q、K，不旋转 V。

## MLP 与张量并行装配

`Qwen3MLP` 和 `LlamaMLP` 都是门控前馈网络。`MergedColumnParallelLinear` 将 gate 与 up 两个输出合并，`SiluAndMul` 沿最后一维对半切分并计算 `SiLU(gate) * up`，最后由 `down_proj` 投影回 `H`：

```python
x = self.gate_up(x)                 # [T, 2I]
x = self.activation(x)              # [T, I]
x = self.down_proj(x)               # [T, H]
```

`main.py` 和 `main_llama32.py` 都为这些模型设置 `ffn_bias=False`，注意力输出投影也固定不使用 bias；但 MLP 构造器仍保留可配置 bias，阅读形状时不能把“类支持 bias”与“示例配置启用 bias”混为一谈。

张量并行主要依靠线性层实现：QKV 与 gate/up 按输出维切片，本地保留相应头或中间维；`RowParallelLinear` 按输入维切片，计算部分结果后用 `dist.all_reduce(SUM)` 得到完整的 `H` 维输出。`VocabParallelEmbedding` 按词表切分，不属于本 rank 的 token 被掩蔽，再将各 rank 的嵌入求和。`head_dim`、`num_heads` 与 `num_kv_heads` 必须满足各层整除约束，不能只依据模型名称任意缩小配置。

## LM Head、权重绑定与检查点装载

`Qwen3ForCausalLM.forward` 与 `LlamaForCausalLM.forward` 都只返回 `self.model(input_ids)`。`compute_logits` 才调用 `self.lm_head(hidden_states)`。在 Prefill 中，`ParallelLMHead` 用 `cu_seqlens_q[1:] - 1` 取出每条序列最后一个 query；在 Decode 中，每条序列本来就只有一个位置。这样采样器收到的是每条待推进序列的一份 logits，而不是整个 Prompt 的词表矩阵。

当 `tie_word_embeddings=True` 时，代码直接执行：

```python
self.lm_head.weight = self.model.embed_tokens.weight
```

因此输出词表投影和输入嵌入共享同一个参数对象，不是训练后再把数值复制成两份。

`ModelRunner` 先将模型移至 CUDA，再调用 `load_weights_from_checkpoint`。装载器读取目录中的全部 safetensors，将 `q_proj/k_proj/v_proj` 沿输出维拼成 `qkv_projection`，将 `gate_proj/up_proj` 拼成 `gate_up`，其余参数优先按 Hugging Face 同名参数直接复制。Qwen3 类虽声明 `packed_module_mapping`，当前装载器实际上按名称模式处理，并未查询该映射；Llama 也走同一套通用合并规则。

还要注意一个实现边界：当前通用装载器主要使用 `param.data.copy_`，没有调用线性层上定义的 `weight_loader` 来逐 rank 切分这些合并权重。普通参数形状不一致时还存在按第 0 维 `min_size` 截断或部分复制的回退，复制成功后仍会把名称加入 `loaded_params`；这不是正确的 TP 分片，加载摘要也可能因此误报。不能仅凭线性层支持张量并行，就推断当前多 GPU 检查点装载已经自动完成正确分片；使用 `world_size > 1` 时应单独核对形状、各 rank 实际数值与加载记录。

## 配置阅读中的两个校准点

第一，`rms_norm_epsilon` 虽被模型和注意力构造器接收，当前两个模型的 `LayerNorm(gamma)` 都没有把该值传进去，实际使用 `LayerNorm` 的默认 `eps=1e-5`。因此 `main.py` 中的 Qwen3 `rms_norm_epsilon=1e-6` 并不会沿这条构造链改变 RMSNorm 的 epsilon。校准模型行为应阅读参数最终落点，而非只看配置字典。

第二，模型支持的二维/三维 QKV 分支、张量并行层和检查点映射是不同层面的能力。引擎主路径采用变长二维排布，示例入口使用具体模型配置；替换模型、启用多卡或修改 RoPE 参数时，需要重新验证整条链路，不能把这些能力简单相乘。

## 实践检查

1. 在 `model_runner.py` 中追踪 `Qwen3ForCausalLM` 的全部构造参数，核对 `num_heads`、`head_dim`、`num_kv_heads` 和 `block_size` 分别传到哪些子模块，标出哪些参数只停留在上层签名中。
2. 对 `world_size=1` 的 Qwen3 配置手算 QKV 宽度：结果应满足 `128 × (16 + 2 × 8) = 4096`；再将 Q、K、V 分别还原成头维形状，解释为什么 K/V 不需要各有 16 个头。
3. 取两条长度分别为 3 和 5 的 Prefill 序列，写出 `cu_seqlens_q=[0,3,8]`，推导演示位置列表为 `[0,1,2,0,1,2,3,4]`，并计算 LM Head 选取的扁平下标 `2` 和 `7`。
4. 用笔展开两个 Decoder 的 `(x, residual)`，确认每次注意力残差和 MLP 残差各被加上一次，且最终 RMSNorm 前没有遗漏末层 MLP 输出。
5. 对比 `qwen3.py` 与 `llama.py`，只列出真正不同的计算：Qwen3 的条件式 Q/K Norm、Llama 3.2 的 RoPE 频率调整，以及二者不同的配置命名和维度。
6. 检查 `layernorm.py` 的默认 epsilon 与调用处实参，判断修改配置字典是否足够；若需要让 Qwen3 的 `1e-6` 生效，应先设计完整传递路径，再增加针对实际模块 `eps` 的检查。
7. 阅读 `loader.py` 的合并与复制分支，区分“网络层有分片装载函数”和“当前装载器实际调用分片装载函数”；用第 0 维不同的普通参数检查截断复制是否仍被记作已加载。另在 TP 大于 1 的 Llama 路径核对 `Attention.num_heads/num_kv_heads`，确认它们与本地 Q/K/V 头数一致。不要在未验证的情况下把单卡装载结论扩展到多卡。

## 小结

MinivLLM 用统一的变长 token 流组装 Qwen3 与 Llama 3.2：嵌入后进入融合残差的 RMSNorm Decoder，QKV 合并投影适配 GQA，注意力按 Prefill/Decode 分流，门控 MLP 恢复隐藏维，最后由独立的 `compute_logits` 产生采样所需 logits。两种模型的主要结构差异集中在 Q/K Norm、RoPE 和具体尺寸。源码阅读还必须落实到参数传递与装载实现：当前模型名匹配是精确的，RMSNorm epsilon 没有按配置透传；LlamaAttn 向 `Attention` 传全局头数会确定性阻断 TP；通用装载既没有自动完成多卡分片，还可能把截断复制误报为已加载。
